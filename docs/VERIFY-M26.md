# VERIFY-M26 — skill authoring (cuts A–E + the Studio)

Date: 2026-09-16 · Spec: `PLAN-M26.md` · Master index: `PLAN.md` §15 M26.

M26 is **complete** except for the two Studio templates that need a reach no skill
has yet (`notes-checklist`, `mcp-call` — they ship with `PLAN-M27.md`). A skill
can now be **made**: described in chat, generated by a model, drawn up from a
template, edited, test-run in the sandbox, installed from either surface (the
Studio button or an approved chat card), forked, edited in place, and
exported/imported as an unsigned bundle.

## The invariants, and where each is pinned

- **Drafting is inert.** No child of `promote` runs on create/update/validate. A
  draft whose entry throws at *import time* still validates `ok` — validation
  reports shape, the dry-run reports behaviour.
- **One install path.** `drafts.promote()` has exactly two callers: the
  `POST /v1/skills/drafts/:id/install` route (capability `skill.install`) and the
  install-approval branch of `POST /v1/tools/pending/:id`. Verified by grep at
  review time, not just asserted.
- **`runDraft()` has exactly one caller** — `POST /v1/skills/drafts/:id/run`.
- **The model cannot install or run.** `core/src/skills/tool.ts` exposes exactly
  two tools (`skills.draft`, `skills.requestInstall`); neither reaches `promote`
  or `runDraft`. `skillAuthorTool.test.ts` asserts the advertised id set contains
  no such tool.
- **Approving executes, so the approver is class-checked.** The approval branch
  runs `capabilityDenial(session.clientClass, 'skill.install')` before promoting —
  the queue is not a way around the class table for the act the table most cares
  about.
- **A widening update needs consent** (409 `permission_change`), a narrowing one
  does not nag, and **both install surfaces produce identical rows** (one
  implementation).
- **Audit discipline**: audits carry ids/counts/lengths/booleans. Asserted by
  serializing the whole audit list in the drafts, bundle and route suites.

## Security fixes the children found and made (not in the spec)

1. **`importBundle` re-points the imported manifest at the new slug.** Without it
   a bundle could name an *installed* skill's id with an identical permission set,
   and `promote` would swap that skill's code with **no consent diff** (D6 only
   asks about a *widened* set). Pinned by a test named for the hole.
2. **`broker.decide` refuses a non-tool row** (`wrong_kind`, cut A) and the new
   `PendingManager.settleInstall` closes an install row — so an install ask can
   never be approved by the path that executes tools.
3. **`stageFromChat` pins the draft's manifest id to the draft's own id** — a
   model cannot re-point a chat draft at an installed skill's id (the same hole as
   1, closed on the other door).
4. **A refusal does not stage the trimmed bundle** — less reach than declared,
   silently, was the alternative.

## Honesty fixes made at review (after the cuts reported green)

1. **The canned generator is now labelled.** With no provider configured (or in
   demo mode) the generator returns a deterministic, valid bundle with
   `model: 'demo'`. The Studio had shown it under the same "generated" chip as a
   model-written draft, which would imply a model wrote it. The rail now says
   *"canned example — no model configured"* for exactly that case, and a test
   pins that a real model id gets no such marker. (`SkillStudio.tsx`,
   `skills-studio-view.test.tsx`.)
2. **Capabilities that cannot be honoured are named errors.** `permissions.llm`
   and `permissions.mcpServers` are shape-validated but **refused** with a message
   saying the runtime cannot do it yet, because M27 wires them. A permission
   summary that promises a reach nothing can deliver is worse than a refusal.
   The Studio's template picker is capability-filtered for the same reason.

Seven pre-existing guard tests fired and were updated **deliberately, not
weakened**: six pinned `SCHEMA_VERSION` to 20 (now **21**) and one pins the closed
capability vocabulary (now including **`skill.author`**, which gates inert

re-baselined for the new `skills` attention destination and its totals, with the
model's no-double-count rule asserted (an open install ask counts under `files`
